## Findings that shaped the design

* Three copies of the Kaggle `postings.csv` are byte-identical (root, `archive/`, `Data/raw`). An earlier
  scaffold had flat duplicate copies of the side tables in `Data/raw/linkedin_jobs/`; they are byte-identical
  to the nested files and loaders read only the nested layout.
* `mappings/skills.csv` holds 35 coarse *job-function* categories, not skills — stored as
  `raw.linkedin_job_functions`, never treated as normalised skills.
* `skills_it.txt` is a resume subset in the same `id:::labels:::text` format, not a skill list.
* O*NET 31.0 renamed files (`essential_skills.csv`, `transferable_skills.csv`, `software_skills.csv`);
  individual technologies have no O*NET ID → stable derived ID `onet-tech:<slug>`.
* RemoteOK descriptions contain double-encoded UTF-8; `common.text.fix_mojibake` repairs only when the
  repair reduces mojibake markers.
* Cross-source overlap is small but real (e.g. 58 Kaggle∩Insights title+company pairs), so sources are
  deduplicated jointly.

## Canonical schemas (`common/schemas.py`)

`Job`: job_id (`<source>:<id>`), source_job_id, source, title, company, company_id, description, location
(+ city/state/country), work_mode, employment_type, seniority, salary_min/max (annualised, 2080 h/yr),
salary_currency, salary_period, industry, skills (source tags only), requirements, occupation,
posting_date, source_url, attribution, is_historical, raw_source_reference, content_hash, raw.
Unknown values are `None` — e.g. DataStax `employment_type` is 100% null in the source and stays null;
Adzuna *predicted* salaries are kept only in `raw`.

`Candidate`: candidate_id, source_document, raw_text, occupations, skills, experiences, education,
credentials, projects (+ total_experience_years, summary). Every fact has `Evidence`
(source_document_id, source_text, start/end offsets, extractor, extractor_version, confidence).

## Ingestion (`ingestion/pipeline.py`)

Chunked CSV reading (20k rows), deterministic hash sampling in development mode
(`configs/settings.yaml: modes.development.max_jobs = 5000`, quota 70% Kaggle / 25% DataStax / 5% RemoteOK),
Parquet output, content hashes. Deduplication (`ingestion/deduplicate.py`): job ID, description hash,
(title, company, location) key, MinHash-LSH (64 perms, Jaccard ≥ 0.85 on 5-word shingles), union-find
clusters, one representative per cluster. Splits are assigned per cluster (70/15/15, seed 13) and checked
for leakage. Development run (with Adzuna): 10,447 records → 8,932 clusters → 4,641 indexable jobs.

**Source-redacted DataStax fields.** In `postings.csv`, 58 titles, 69 companies and 68 locations are replaced by asterisks (`**** *********`). A redacted value is unknown, not a value: company/location become `None`, the row records `raw.masked_fields`, and a posting with a redacted title is kept in `jobs.parquet` (row order, clusters and splits stay stable) but is not indexed (66 rows in the development run; 52 had been indexed before this rule). The cluster representative prefers a readable title, so a redacted copy never displaces its readable twin (3 postings regained their place). Titles are never reconstructed from the asterisk pattern.

`python scripts/ingest_data.py --full` ingests everything (~124k Kaggle postings); `--fetch-live` pulls
RemoteOK and, with credentials, Adzuna.

### Adzuna notes

* Locations come from Adzuna's structured `area` list (country → state → … → locality); 768/800 have a US state.
* Descriptions are ~500-character snippets, so few skills are extracted per job (many have none).
* 757/800 salaries were Adzuna *predictions*; they are kept in `raw` only and shown as unknown.
* Employers repost identical ads across many locations (e.g. one customer-service ad ×55); deduplication
  keeps one representative, so 394 of 800 Adzuna jobs are indexed.

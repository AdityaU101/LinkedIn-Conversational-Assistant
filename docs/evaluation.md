# Evaluation & annotation

```bash
python scripts/evaluate.py                       # all experiments -> Data/results/*.json
python scripts/evaluate.py --only B C classifiers
python scripts/create_annotation_tasks.py        # task files under Data/annotations/
```
The research dashboard reads `Data/results/`. Rule: a metric is reported only when it was computed from
real labels or real runs. Otherwise the experiment is `not_evaluated` or `blocked` with the reason, and the
dashboard shows **Not evaluated**. Descriptive statistics (latency, overlap, coverage) are labelled as such.

## Results recorded so far (dev mode, seed 13)

* **Occupation family LR** (SOC major group, 7,986 held-out O*NET alternate titles): accuracy 0.791,
  macro-F1 0.772.
* **Kaggle resume category LR** (24 classes, 2,484 resumes, stratified 5-fold CV): accuracy 0.661,
  macro-F1 0.606.
* **B — occupation normalisation** (1,000 held-out O*NET alternate titles, lexicon exact-match disabled):
  top-1 exact O*NET code — classical 0.251, embedding 0.170, hybrid 0.295; major-group accuracy 0.416 /
  0.290 / 0.500; coverage 0.545 / 0.405 / 0.675.
  Synthetic skill-surface diagnostic (NOT gold): top-1 0.651 / 0.678 / 0.730.
* **C — graph structure** (120 test-split jobs + 60 resumes, identical documents):
  ontology graph — 362 entity nodes resolving to 291 taxonomy concepts, duplicate-node rate 0.000,
  3 relation types, schema conformance 1.000, grounded edges 0.981 (the rest are source-provided tags
  without a text span); free-form SPO graph (spaCy dependency triples + a resume-bullet heuristic) —
  5,429 nodes of which only 70 resolve to taxonomy concepts, duplicate-node rate 0.010, entity
  fragmentation 1.10, 1,420 distinct predicates (fragmentation 0.278), schema conformance 0.000.
* **F — template explanations, automatic verifier** (60 explanations): citation validity 1.0, faithfulness
  1.0, hallucination rate 0.0. Template explanations are faithful by construction, so this mainly checks
  that the verifier does not over-reject; it is not evidence about LLM explanations.
* **D — descriptive only**: mean latency per query (ms) BM25 88, TF-IDF 39, Jaccard 39, dense 31, RRF 31,
  LTR/fallback 31, final (incl. cross-encoder + MMR) 396.

All numbers are regenerated by the scripts; check `Data/results/*.json` for the exact values and settings.

## Metrics

* Extraction: exact-span and relaxed-overlap P/R/F1 per label and micro (`evaluation/extraction.py`).
* Ranking: graded nDCG@10 (gain 2^rel − 1), MRR (rel ≥ 1), P@5 (rel ≥ 1) on condensed lists (unjudged
  documents removed — pooled, incomplete judgments; `evaluation/ranking.py`).
* Graph: duplicate-node rate, entity fragmentation, predicate fragmentation, schema conformance,
  grounded-edge rate (`evaluation/graph.py`).
* Explanations: citation validity, faithfulness (= supported / factual sentences), hallucination rate.
* Providers: latency/doc, tokens/doc, grounding rate, cost per 1,000 documents (null when pricing unknown).

## Annotation (`annotation/`, `Data/annotations/`)

| Task | Files | Target |
|---|---|---|
| Extraction | `extraction/tasks.json` (Label Studio, `label_studio_config.xml`), write `annotations.jsonl` | 150 documents, double-annotated |
| Skill normalisation | `normalization/tasks.csv` → `gold.csv` (system predictions hidden in `*_HIDDEN.csv`) | 500 mentions |
| Relevance | Annotation page in the app, or `relevance/pool.csv` → `judgments.csv` (0/1/2) | 40 profiles × 20 pooled jobs = 800 |
| Graph edges | `graph/edge_validation_tasks.csv` → `edge_validation.csv` | 100 edges |
| Explanations | `explanations/faithfulness_tasks.csv` → `faithfulness.csv` | 60 explanations |
| User study | `user_study/PROTOCOL.md`, `responses.csv` | 15–20 participants |

Pools are built by depth-k pooling over every ranking method, shuffled, with method names hidden.
Agreement: Cohen's κ (nominal/linear/quadratic), Krippendorff's α (nominal/ordinal), span F1
(`annotation/agreement.py`). Once ≥ 200 judgments over ≥ 10 candidates exist, train LambdaMART with `python scripts/train_ltr.py`
(add `--no-graph` for the graph-feature ablation, which is not saved as the serving model); the pipeline uses
the saved model automatically from then on. Evaluate with Experiment D.
